Cropping Many Images to One Uniform Size

Photos come in all sorts of resolutions, and that quickly becomes a problem. This tool crops any number of differently sized photos to one uniform size and hands them back as a single ZIP. Because position is expressed as a percentage, mixed portrait and landscape shots still line up.

What this tool is for

The third tool on the home screen, Batch image cropper, does exactly one thing: it crops many photos to the same size and saves them as PNGs. Whatever the input dimensions, every output shares one pixel size. That makes it useful for building thumbnail sets, preparing card images for the web, or matching a fixed resolution for print.

There is no background removal here. Solid-colour removal exists only in the grid cutter, so if you need transparency you would use both tools in sequence.

The workflow

Select several photos

Opening the tool shows the prompt "select several photos to crop" and a Select photos button. You can choose many files in one go. Add more later with Add, or start over with Clear all.

Files that cannot be decoded are skipped automatically, and you are told so: {n} files could not be read and were skipped. This happens often when a folder mixes PNG, JPG and WebP. Only images that actually opened stay in the list. Despite the wording, these do not have to be photographs — any decodable image works.

Pick a reference photo

At the top of the list you get {n} photos along with the reference line Reference: {name} • {w}×{h} px. The strip shows thumbnails of the remaining images. Tapping one makes it the reference, and both the preview and the size baseline change with it.

The reference plays two roles: it is what the result preview displays, and it is what your crop size is compared against. Choosing the photo you think will crop most gracefully makes the upscaling question easy to judge.

Enter the crop size

In Crop size you type a width and a height in pixels. The default is 1920 × 1080, and each side accepts anything from 8px to 20000px.

If the size you ask for is larger than the reference photo, the image is upscaled and cropped automatically, and you get the warning This is larger than the reference photo. It will be upscaled before cropping. Upscaling computes new pixel values rather than simply stretching, so enlarging a low-resolution photo can invent texture that was never there.

Adjust the crop position

The Crop position section says "drag inside the rectangle to move it to the position you want". Two sliders handle width and height, both expressed as percentages running from -100% to +100%, where 0% means centred. A negative value does not mean a limit was reached; it pushes the rectangle off the original by that proportion of the photo's side length.

You can also drag the rectangle directly in the preview and the values follow. That is often quicker for fixing composition, after which the sliders handle the remaining fine tuning. Press Centre to send both values back to 0.

The summary line underneath spells out what will happen, either "centre-aligned crop of all photos to {W} × {H} px" or "crop at {x}% horizontal · {y}% vertical position to {W} × {H} px". Reading that one line before saving is the fastest confirmation that your settings mean what you intended.

Save

The preview, titled Result preview ({W} × {H} px), shows only the selected reference photo. What the other photos will look like you can judge after saving, because the identical settings are applied to all of them.

Finally press Save as ZIP ({n} photos). The hint reads "you can also save with Ctrl+S", and Cmd+S works the same way on a Mac. Useful when you are repeating the operation many times.

File naming

Each photo produces one PNG named after the original with .png on the end. When names collide you get _2 and _3 suffixes, so hero.png, hero.jpg and hero.webp selected together come back as hero.png, hero_2.png and hero_3.png — nothing is silently overwritten or lost. The rest of the original name is preserved, so the only visible change is the format.

The archive itself is named crop_{W}x{H}_{count}.zip, which records the output size and the photo count in the file name alone.

This ZIP contains PNGs only. Unlike the archive from the grid cutter, it has no index.html and no stage.jpg, because an unrelated set of photographs has nothing to animate.

Why positions are percentages

Using ratios rather than absolute coordinates is the point of this tool. Imagine a folder holding both tall phone photos and wide camera shots. Set the horizontal position in pixels and, on photos with a shorter side, that value points somewhere completely different — the crops end up inconsistent. A value of 0% means the centre of each photo, so moving every photo by the same percentage produces the same framing everywhere.

Since any upscale gets harsher the further you stretch, the safest reference photo is the smallest one in the set. Related size calculations are covered in the pixel art image specifications guide.

Quick checklist

  1. Did you tap a thumbnail to choose the reference photo?
  2. Is each crop side between 8px and 20000px?
  3. Does width × height stay under 40,000,000?
  4. Does the summary sentence describe what you meant?
  5. If an upscale warning appeared, is the source resolution really enough for that output?
