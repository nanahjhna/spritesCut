Previewing Animation with the ZIP and index.html

Pressing save once does not just hand you PNGs. The archive also contains an index.html that plays those frames back in order, plus a stage.jpg used as the preview background. Open the folder and the animation is on screen immediately.

Published 2026-10-04 · Last updated 2026-10-04 · About 8 min read

What is actually inside the ZIP

The grid cutter never gives you a single image file. Saving produces a ZIP archive, and that archive holds three kinds of item: the cropped frame PNGs, a generated HTML preview page, and one bundled background image. Unzipping it gives you both the usable assets and the verification file, already sorted together.

Anatomy of the saved ZIP
ItemNamingPurpose
Frame PNGs{filename}_{columns}_{rows}_1.png … _N.pngThe actual output. The numeric suffix is the frame order.
Preview pageindex.htmlPlays the frames back in order for verification. Makes no network requests.
Background imagestage.jpgThe image used as the preview backdrop.

Names follow a fixed pattern. The archive itself is called {filename}_{H}_{V}.zip, with the horizontal and vertical split counts appended, and the frames inside use {filename}_{H}_{V}_1.png and so on. Characters that are unsafe in a filename become underscores, and an empty name falls back to sprite.

Only this ZIP carries index.html and stage.jpg. The ZIP from the batch image cutter contains one PNG per photo and nothing else, because a grid of unrelated photographs is not an animation.

Walking through a save

Load the sheet and set the split counts

Open the grid cutter from the home screen and load your sheet with the Upload image button. Once an image is loaded the panels for Background, Split counts (columns × rows) and Split mode appear in order. If your frames sit in a single horizontal strip you mostly need to get the column count right. The status bar at the bottom shows the full size, the crop region, the single-frame size and the total frame count, so checking the per-frame size there is the fastest sanity test.

Press save and download

When the numbers look right, press Save and download (ZIP). The button turns into Processing… while the frames are bundled, and a preview the sprites to save dialog opens afterwards. Its header shows the total frame count along with ({k} deleted). Anything you would rather not keep can be dropped here before the archive is written.

Group frames with folder organisation

That dialog has a Folder organisation switch: "creates folders to tidy up the images". It is on by default, and while it is on the ZIP gains folders that the images are placed inside.

The sidebar lets you move between Show all and Default (no folder), and Add folder creates folders named New folder 1, New folder 2 and so on. Any folder can be renamed or removed. Deleting a folder never deletes images: they move back to the default location, and you first get a confirmation explaining that the {n} images in folder "{name}" will be moved to Default (no folder).

There are two ways to move images into a folder.

  1. Long-press for half a second, then drag. Hold an image for roughly half a second to pick it up, then drag it onto a folder in the sidebar and let go.
  2. Select, then press Move. Select one or more images, press Move, and pick the destination in the choose folder to move to dialog.

Multi-selection works with Ctrl-click and Shift-click, and a Select mode toggle keeps the selection active for further taps. The tooltip reads "Select mode (select multiple)".

Delete selected increases the deleted count in the header. Once you finish, the remaining frames are renumbered sequentially from 1 — and that numbering restarts inside every folder. Six frames in the first folder and four in the second will be saved as 1–6 and 1–4 respectively. One folder is effectively one animation, which is the natural way to separate a walk cycle from a run cycle found on the same sheet.

Unzip and open index.html

Press Download (ZIP), then the sequence is simple.

  1. Double-click the downloaded archive to unzip it.
  2. Double-click index.html inside the folder.
  3. The animation starts playing in your browser.

That HTML file reads nothing from the network. Every frame PNG is loaded up front when the page opens and afterwards the page only draws them, so it works on a tablet in airplane mode or from a USB stick on a different machine.

The play button and the FPS slider

The page is headed Sprite animation preview, followed by an info line in the form {n} frames ({w} × {h}px). A single button toggles between Pause and Play. The Playback speed (FPS): slider ranges from 1 to 30 FPS and defaults to 10. Playback starts automatically when the page loads, so you can just watch the first loop before touching anything.

Take only the PNGs to your engine

Once you are satisfied, deleting index.html and stage.jpg costs you nothing — the output is unaffected. What an engine needs is the PNGs. If you used folders, each folder is a ready-made unit you can import as a whole, which makes pulling several animations out of one sheet much less work.

What stage.jpg does

stage.jpg becomes the backdrop of the preview, applied with background-size: cover so it fills the box. In practice it is a floor or wall painting that lets you judge how transparent regions will look once the sprite stands on a real backdrop.

If the file is missing, renamed or damaged, the preview simply opens without it and a CSS checkerboard pattern takes over, making the transparent pixels easy to see. The background is decoration; the animation plays either way.

The preview box is capped at 400px wide with the aspect ratio preserved. Frames are drawn with image-rendering: pixelated, so the pixel grid stays crisp even when the sprite is displayed far smaller than its native size.

Practical tips

  • Check the FPS first. Game animation usually runs at 10 to 12 FPS, which is close enough to the 10 FPS default that you rarely need to move the slider.
  • Read frame count and frame size together. The per-frame size appears in the info line as {w} × {h}px. If the column and row counts are not in a ratio your sprite actually uses, you will get unwanted empty margins around each frame.
  • Trim the leftover padding. The margins in equal mode remove repeated empty space, and less transparent padding also means a smaller PNG. The margins and manual boundaries guide covers this in detail.
  • Fix odd per-frame sizes before exporting. Each frame can be given its own size from the results preview, and those values are what the ZIP uses. See the per-frame editing guide.

Summary

The grid cutter's ZIP holds three things: frame PNGs, an index.html playback page, and a stage.jpg backdrop. The HTML runs fully offline and plays between 1 and 30 FPS, while a missing stage.jpg falls back to a checkerboard. Using folder organisation in the save dialog means a single pass can organise several animations at once.
