Precise Splitting with Padding and Manual Boundaries

A clean grid needs one equal split. Real sheets rarely cooperate: transparent gutters between frames, a last row only half filled, frames of differing widths. Two features solve this, and they are worth understanding before you fight with your layout.

Three situations where equal splitting fails

Diagnose the cause first, because each cause has its own fix.

Transparent gutters between frames

Exporters and editors often leave a transparent margin around every frame. If your sheet is 512 × 128 but contains four 32 × 32 sprites spaced 32px apart, a four-way split yields 128 × 128 cuts where the sprite hugs one corner and the rest is empty. In motion, the sprite looks like it is jittering in place.

A partly filled last row

Nine frames in a 4 × 4 grid leave the bottom row half used. The final cut is entirely transparent: more files, no extra art. The frame-count maths in the status bar makes this obvious before you save.

Frames of different widths

Directional character sheets, or non-square parts such as a 2:1 banner, cannot be cut by a single division. Every value you try leaves an error, and because the error differs per frame, the animation wobbles.

Key point Gutters are solved by padding; uneven widths need manual mode. The two features compose: padding still applies in manual mode, so the most reliable order is to strip the outer transparent margin first, then place boundaries inside the region you have left.

Step 1. Load the sheet and find the mismatch

Open the image cutter from the sprite sheet tool and load your image. The canvas shows it at 100%, with a checkerboard behind transparent pixels. Everything outside the guide box is dimmed, grid lines cross the region, and each cut carries a numbered chip. Those numbers match the frame indices of the export, so spotting a wrong cut now saves hunting later.

Step 2. Trim the outer margin with padding

While the mode is equal split, the padding section exposes four fields. The "region padding (top / bottom)" group holds the top and bottom values, and "region padding (left / right)" holds the left and right ones, all in pixels.

Typing a value applies it immediately, and dragging the canvas handles updates the same numbers. Pick whichever you prefer: typing is precise, dragging is fast for rough trimming. A good rhythm is to drag the region roughly inwards, then finish with exact numbers.

Take the earlier example. A 512 × 128 sheet holding 32 × 32 frames at 32px pitch needs 16px of left and right padding, after which the region is 480px wide and four cuts of 120px each line up with the artwork. Confirm against the thumbnails as you go rather than trusting the arithmetic alone.

Step 3. Switch the split mode to manual

Select manual in the split mode segment. Boundary fields appear, and the padding values you set in step 2 stay active — which is exactly why finishing that step first makes the coordinates easier to reason about.

Step 4. Enter boundary coordinates

In manual mode, cuts are defined by where the dividing lines sit. The two helper lines read, verbatim:

"Horizontal boundary position (px) — absolute coordinate per vertical line • 0 ~ image width" and "Vertical boundary position (px) — absolute coordinate per horizontal line • 0 ~ image height".

In other words, the horizontal boundary N fields hold the x position of vertical lines, and the vertical boundary N fields hold the y position of horizontal lines. The space between the left image edge and the first boundary is cut 1, the space between two adjacent boundaries is the next cut, and so on to the right edge. Removing one boundary removes one frame.

Values are absolute pixel coordinates of the source image. If you have zoomed the browser, you still type image coordinates, not screen coordinates.

Step 5. Learn the clamping rules

You can type freely, but the result is protected. A boundary can only move as close as 10px to its neighbour; push it further and it stops there. The first and last boundaries cannot leave the image bounds.

These constraints stop a cut from collapsing or inverting by accident. They also mean a frame narrower than 10px is impossible in manual mode — if you need something that small, the source sheet has to be rescaled or relaid out. The minimum value shown in the status bar frame-size range tells you when you have hit that floor.

Step 6. Verify and save

In manual mode the status bar adds a "manual" badge and replaces the single frame size with a minimum to maximum range, because cut widths genuinely differ. Full size, region size with padding, and total frame count with the C×R arrangement remain as before.

Then open the result preview and compare each thumbnail's label with the range from the status bar. If a single cut is still off, finish it with per-frame editing, described in per-frame editing and undo.

Every boundary edit is recorded in the undo history, so experiment freely and press Ctrl+Z to back out. If a sequence of tweaks left the layout tangled, the "reset to even spacing" button redistributes the boundaries evenly across the current region, giving you a clean starting point.

Using padding and manual mode together

Order matters when you combine them. This sequence stays predictable.

  1. Load the image and, in equal split mode, use the four padding fields to strip the outer transparent margin.
  2. Check the region size in the status bar to confirm the remaining area is what you intended.
  3. Switch the split mode to manual and enter boundary values matching the number of cuts you want.
  4. Read the "manual" badge and the frame-size range in the status bar.
  5. Inspect every cut in the result preview and fix stragglers with per-frame editing.
  6. Press save and download (ZIP), confirm in the preview dialog, then download the ZIP.

For details on step 5, read per-frame editing and undo. To check playback after export, see the ZIP and index.html guide. If the background is a solid colour, background removal turns it into a transparent PNG.
