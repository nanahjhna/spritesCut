Converting a GIF into a Sprite Sheet

Turning an animated GIF into a still image bundle makes it far easier to hand to a game engine. Pick a GIF in the browser and the frames are separated straight away, then download them as a strip, a grid, or a set of loose files.

Published 2026-10-04 · Last updated 2026-10-04 · About 8 min read

Why convert at all

A GIF plays by itself, but game engines usually load a single sheet image and cut it up using frame indices. What they need is therefore "a picture of the animation played once". That is the only job this tool does. Once the GIF is selected every frame is decoded, split apart, and arranged according to a layout you pick — and that is already a usable sprite sheet.

There is one important difference worth knowing about. A GIF can give each frame its own display duration, but a PNG has nowhere to store timing information. The PNG output produced here carries no per-frame duration, so playback speed has to be configured on the engine side. Around 12 FPS is a reasonable starting point if you want the original rhythm.

The conversion workflow

  1. Load a GIF and check its frame count and dimensions.
  2. Choose how to arrange the frames: a single row, a single column, or a grid.
  3. Tidy each frame with automatic transparency trimming and solid-colour background removal.
  4. Press one save button for the output shape you need.

Pick a GIF file

Open the GIF sprite splitter from the home screen. The screen is titled GIF sprite splitter and starts with only the prompt Select a GIF file and a Select GIF button. Press it and choose your file. Once a file is loaded the button reads Change so you can swap it for another one.

Read the frame info and watch the preview

Once the file is decoded an info line appears in the form {n} frames • {w}×{h} px • {x.xx}s, giving you the frame count, the per-frame size and the total duration at a glance. Directly below it, 1 cut: {w} × {h} px states the size of one frame, and that is exactly the size of one cell in the finished sheet.

A live animation preview sits near the top of the screen. Its playback is fixed at roughly 80 milliseconds per frame — about 12.5 FPS — and is not user adjustable. It is rendered 400 pixels wide using nearest-neighbour scaling so pixel art stays crisp, on a checkerboard background that makes the transparent region obvious.

Choose the sheet layout

Under Sheet layout you pick one of three options. The default is Single row.

Resulting sheet size per layout (frame {w}×{h}, {n} frames)
LayoutSheet widthSheet heightGood for
Single roww × nhSimplest maths — no division needed. Right choice when a strip sheet is already what you want.
Single columnwh × nConstrained widths, or aligning frames to a vertical scroll axis.
Gridw × ch × rColumns are set to c = ⌈√n⌉ and rows to r = ⌈n ÷ c⌉. Keeps the result close to square, which is easier to sample.

For the grid layout the column count is the square root of the frame count, rounded up. With 10 frames you get 4 columns (⌈√10⌉ = 4) and 3 rows, so 4×3 = 12 cells with only 10 filled. The result is captioned Sheet result: {W} × {H} px ({C}×{R} = {n} cuts). At 900 pixels of viewport width and above the sheet preview sits beside the animated preview, and below that width the two stack vertically. Seeing them side by side is the quickest way to confirm that the frames match the source GIF.

Trim transparency and solid backgrounds

Remove transparent areas automatically carries the explanation "keeps only the opaque area of every frame" and is on by default. With it enabled, the bounding box of all opaque pixels is computed across the whole animation and everything outside that common region is trimmed. GIFs frequently contain frames whose transparent margins shift slightly; trimming keeps the artwork from wobbling and removes dead space around the edges. Turn it off when the differing empty margins are themselves meaningful to you.

Remove solid background is off by default and described as "detects the edge colour automatically". When enabled, the detected colour is shown as Background colour RGB(r, g, b) and matching pixels are removed. Detection samples an 8% band along the border of the first frame and takes the dominant colour there, then reuses that single colour for every frame. That is what keeps the result stable even when the background shifts slightly between frames. On an image that is not a solid colour you will get the message "could not detect a background colour — please check whether the background is a single colour".

The Tolerance: {n}% slider below spans 1% to 50% and defaults to 10%. Higher values remove more near-matching pixels. Results are recomputed after a 150ms debounce while you drag, and a slim progress bar appears underneath so the slider stays usable during that time. A truly flat background needs only 1–5%; a noisy one may need 20% or more. The detection logic itself is covered in the background removal guide.

Save the output you need

Three save buttons sit at the bottom of the screen.

Save buttons and the files they produce
ButtonFile nameWhat you get
Sprite sheet (PNG){filename}_sheet.pngA single image with all frames combined in the chosen layout. All you need when the engine expects a sheet texture.
Frames PNG set (ZIP){filename}_frames.zipOne cropped PNG per frame plus index.html and stage.jpg. Best when you want to manage frame files individually.
Save GIF again{filename}.gifA re-encoded GIF, saved so that it loops forever.

Check naming and the preview files

Inside the frames ZIP, files are named {filename}0001.png and onward, zero-padded to four digits, so the order is 0001, 0002, and so on. Past 9999 frames the padding grows to five digits and continues from 10000. Because the numeric order matches playback order you never need to renumber anything.

The ZIP also carries index.html and stage.jpg, generated exactly as described in the grid cutter preview guide. Unzip it, open index.html, and the converted animation plays straight away.

GIF frames are stored in a limited palette, so each one is converted to RGBA before compositing. Semi-transparent pixels and transparent areas therefore survive into the sheet instead of being flattened away.

Choosing between the three outputs

Troubleshooting

Symptoms and what to check
SymptomWhat to check
The GIF will not open at all.It may be an unsupported file. If you see "the GIF file could not be decoded", try a different file.
The frame count shows zero.The file has no frames, and "the GIF has no frames" is shown alongside it.
Frames look misaligned in the sheet.Usually caused by automatic transparency trimming. Switch it off and compare.
Background detection keeps failing.The edges are not a solid colour. Do not use this switch on non-flat GIF backgrounds.
Parts of the character get deleted.The tolerance is too high. Lower the slider.
The sheet is extremely wide.Switch the layout to Grid and the dimensions shrink to nearly square.
The slider feels frozen while dragging.Reprocessing starts after a 150ms delay and the progress bar underneath shows it. Releasing the handle finishes immediately.

This tool has no undo history and no keyboard shortcuts. If you change a setting by mistake, pressing Change and re-selecting the same GIF returns everything to the defaults. If what you actually need is a sheet cut into separate PNG files rather than a GIF conversion, the basic sprite sheet cutting guide is the better fit.
