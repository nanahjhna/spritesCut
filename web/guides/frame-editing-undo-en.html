Per-Frame Editing and Undo/Redo

Most cuts are right and only a few sit half a pixel out. You do not have to rebuild the whole grid for that: pick one frame from the result preview, correct it, and if you make it worse, put it back with a single keystroke.

Published 2026-10-04 · Last updated 2026-10-04 · About 8 min read

Why you would edit one frame

Checking the results after cutting tends to reveal two kinds of problem. One is a few bad frames: padding off by a little, or a partly filled last row leaving a cut mostly transparent. The other is one frame that is almost right: an outline missing a pixel, or a sliver of background dragged in beside a front-facing character.

Fixing either of those by reworking the split counts cascades into the padding values and ends up messier than before. Per-frame editing exists for this case. The grid stays exactly as it is, and a single frame gets its position and size overwritten.

Important Per-frame overrides belong to the current grid. Changing the column or row count changes how many frames exist and where they sit, so the overrides reset. If you plan to try several grid combinations, you cannot carry each set of edits between them; finish one layout and adjust it.

Step 1. Open the result preview

Open the image cutter from the sprite sheet tool, load your image, and expand the result preview panel at the bottom. The panel collapses and expands, which is handy: keep it closed while testing grid counts, and open it once a result looks plausible.

Expanding it shows a thumbnail grid on a checkerboard that represents transparency. The header reports the total as "{n} cuts", and a reset all button appears whenever at least one override exists. That button's presence is a useful signal: it means this sheet has been hand-tweaked.

Step 2. Read the thumbnail labels

Every thumbnail carries a label of the form "index · width×height". A tile reading 7 · 128×128 tells you frame 7 of the output is 128 × 128. Thumbnails are scaled down to fit the panel, but the label always shows the true pixel values, so scanning the grid reveals an odd frame immediately.

Look at the checkerboard too. A tile with a lot of remaining background next to a clean transparent one tells you which section needs attention for the keying problem described in background removal.

Step 3. Enter single-frame edit mode

Tap the thumbnail you want to fix and the tool switches to "frame N edit" mode. The canvas changes with it:

  • Instead of the full grid, only the selected frame gets handles.
  • The dimming outside the guide box is switched off, so the whole source image is evenly lit and neighbouring frames can be used as reference.
  • Dragging the handles changes that frame's position and size.

When you need to check several frames, press end edit to leave, then tap the next thumbnail. Repeating enter-and-exit keeps each adjustment isolated.

Step 4. Adjust x, y, w, and h

The editor shows four fields: x, y, w, and h. x and y are coordinates in the source image; w and h are the width and height of the region being cut. Dragging and typing produce identical results.

Two rules apply. The minimum frame size is 8 × 8 px, and smaller values are rejected, so if your source resolution simply is not there, you must export a larger sheet. And results are recomputed after roughly 150ms, so if you type into several fields in quick succession only the final value may seem to take effect; wait a moment before judging it.

Coordinates are integer pixels of the source image, no matter how far you have zoomed the browser.

Step 5. Restore defaults, or everything

There are two ways to undo an edit, at two different scopes.

Default reverts only the frame you are editing to its grid value. Adjustments on other frames stay put, which is exactly what you want after working through a long list and spotting one mistake.

Reset all clears every per-frame override in one action. Use it when you have spent twenty attempts on boundaries or padding and want a clean baseline — this replaces the manual procedures described in padding and manual boundaries. The button only appears when overrides exist.

When you are finished with a frame, press end edit. Your overrides are kept and carried into the export.

Step 6. Undo and redo

Every value-changing action is recorded: dragging a boundary, typing a padding number, editing a frame. History holds up to 100 steps, and consecutive changes to the same target within 0.35 seconds merge into a single step.

The reason that merge matters is practical. A single handle drag can produce sixty value changes. Without merging, one Ctrl+Z would not return you to where the drag started, and you would have to press it sixty times. With merging, a drag is one step, and one keystroke returns you exactly to the state before it.

The shortcuts are:

Image cutter shortcuts
ShortcutActionNotes
Ctrl + ZUndoReturns to the previous state
Ctrl + Shift + ZRedoReapplies an undone change
Ctrl + YRedoSame action as Ctrl + Shift + Z
Ctrl + SSaveSaves the ZIP in the batch image cutter

Loading a new image clears the history completely. Once the source changes there is no reason to step back to the previous file's state. By contrast, history keeps accumulating while you keep adjusting boundaries on the same image, so re-select the file if you want a guaranteed clean slate after a long experiment.

A practical routine

When a task involves a lot of trial and error, this order keeps you out of trouble.

  1. Set the grid counts and confirm the total and per-frame size in the status bar.
  2. Open the result preview and scan the labels to see whether every frame matches.
  3. Open only the outliers and adjust their position and size.
  4. Press Ctrl+Z if one change went wrong, or reset all if you want the untouched baseline back.
  5. End edit, then use save and download (ZIP) and confirm in the preview dialog.

Once the frames look right, the ZIP and index.html guide shows you how to watch them actually move. If your source frames come from an animated GIF, the next natural step is converting a GIF into a sprite sheet.
