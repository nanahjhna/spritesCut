Basic Sprite Sheet Cutting

A regular grid sheet needs nothing more than an equal split. Pick one image, type two numbers, and you get a folder full of PNG frames. Here is the whole path, start to finish.

When this method works

Equal splitting is exact when every frame in the sheet is the same size, there is no gutter between frames, and each row holds the same number of cuts. Divide a 512 × 128 sheet 4 × 2 and you get eight 128 × 64 frames — nothing else to do.

It breaks down when transparent margins sit between frames, or when the last row is only partly filled. In that case move on to padding and manual boundaries. For now, let's take a plain grid all the way apart.

Step 1. Choose the image

Open the sprite sheet tool and switch to the image cutter on the home screen. With nothing loaded, the page shows only the prompt "스프라이트 시트를 업로드해 주세요" (please upload a sprite sheet). Click it, or use the file picker button, and select your image.

PNG and JPG work, as do other formats your browser can decode. The moment you pick the file it is read locally and drawn on the canvas at 100%. There is no server involved, so nothing is transmitted and a slow connection will not slow down the work.

Loading an image also clears the undo history, so records from a previous file can never bleed into the new one.

Step 2. Enter the grid counts

In grid (columns × rows), type into two fields labelled with the horizontal and vertical split; each carries the suffix "ea". They start at 4 × 1. The table shows what common settings produce.

If you clear a field and leave it empty, that side is not calculated at all, so type a replacement straight away. Entering zero or a negative number falls back to 1 for that side. Either way, glance at the status bar after typing to make sure the result matches your intent.

While the mode is set to equal split, four padding fields are available. Enter how many pixels to exclude from the top, bottom, left, and right, and the drag handles on the canvas move with them. Fine-tuning gutters is covered in padding and manual boundaries.

Step 3. Read the status bar

The bar under the canvas summarises everything that matters:

  • Full W×H px — the size of the original image.
  • Region W×H px (T/B/L/R) — the area left after padding is excluded.
  • 1 cut W×H px — the size of one exported frame.
  • Total N (C×R) — how many frames you get, and the arrangement.

Because the bar updates as you type, you can confirm each change without guessing. With a 1024 × 1024 image and 8 × 8, it must read 128 × 128 per cut and 64 total. If the frame size comes out as zero or under 8px, the grid is too fine — reduce it. The smallest frame the cutter will produce is 8px.

Switch the mode to manual and the bar adds a "manual" badge. Since cut sizes can then vary, it also shows the smallest to largest frame size as a range.

Step 4. Check the result preview

The result preview panel at the bottom collapses and expands. Open it and the frames appear as thumbnails on a checkerboard, so transparency is easy to see. Each tile is labelled with its index and dimensions, such as 12 · 64×64, meaning frame 12 of the output is 64 × 64.

These thumbnails are produced by the same calculation as the final export. If what you see here disagrees with the guide lines on the canvas, your grid counts or padding values are off — better to fix it now than after export. Tapping a thumbnail opens a single-frame editor for that frame, described in per-frame editing and undo.

Note Output is always PNG. There is no JPG or WebP option, because alpha transparency has to survive the export.

Step 5. Remove frames you will not use

Sheets often contain cuts you never wanted: an empty slot at the end of the last row, a reference pose, a duplicate. You can trim individual frame sizes in the preview, or delete frames outright from the save dialog that appears just before download.

In that dialog, press the "delete" badge on any tile to remove it. The remaining frames are renumbered from 1 with no gaps, so deleting frames 5 and 7 renumbers everything after them.

If your scenes belong to different animations, use the folder feature in the sidebar. Turn on folder mode, create folders with "add folder", then long-press an image for half a second and drag it into a folder — or select several and use the "move" button. Ctrl-click and Shift-click also multi-select, and the "select mode" toggle keeps selection active for repeated picks. Numbering restarts inside each folder, which keeps an idle loop and a run cycle in tidy separate ranges.

Step 6. Save the ZIP

When you are satisfied, press save and download (ZIP). The label switches to "processing…" while the frames are cut, and then the "save preview" dialog opens. Confirm your selection there and press "download (ZIP)". Saving is deliberately two steps: cut first, then verify what will actually be written.

The dialog footer spells out the naming rule. For a source file called hero.png with a 4 × 2 grid, the archive holds hero_1.png through hero_8.png. Unsafe filename characters become underscores, and an empty name falls back to sprite.

One more detail: the ZIP also contains index.html and a background image stage.jpg alongside the PNG frames. Unzip and open index.html in a browser to watch the frames play back in order. The ZIP and index.html guide covers that in detail.

Choosing grid counts

If the image is open and you are unsure what to type, work through this list.

  1. Confirm the source size from the full W×H px readout.
  2. Decide the intended size of one cut. For pixel art, powers of two such as 32, 64, or 128 are safest.
  3. Divide the full width by the cut width for the column count, and the full height by the cut height for the row count.
  4. Check that the total and per-frame size in the status bar match what you expected.
  5. If they differ, apply padding first, or adjust the counts one step at a time.

Take a 1024 × 512 sheet holding 64 × 64 sprites: columns is 16 and rows is 8, giving 128 cuts of exactly 64 × 64. When the arithmetic refuses to land cleanly, the per-frame size is turning fractional — the fastest fix is to bring the source size or the target cut size onto a power of two.

There is no frame-count ceiling in code, but every frame duplicates image data, so device memory is the real limit. Cutting a 1024 × 1024 sheet into 256 tiles of 64 × 64 means 256 separate files, each anywhere from tens to hundreds of kilobytes depending on the content. Very large sheets are safer processed in batches.
